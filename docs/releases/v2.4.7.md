# AltForge v2.4.7

- Status: Release preparation; not yet published
- Version: 2.4.7 for iOS AltForge, macOS AltForge Server and Windows AltForge Server
- Change: CHG-20260905-004; ISSUE-20260905-004
- Release: https://github.com/legeling/AltForge/releases/tag/v2.4.7
- AltSign: unchanged from v2.4.5 (`9b06df71234804204bbbcb65ed135edd0d15b8cb`)

## 更新内容

- 修复官方更新源漏写本地网络权限声明，导致应用内更新触发 `AltStore.VerificationError 201` 的问题。
- 发布时使用统一审核的权限清单；对真实 IPA 主应用和扩展检查隐私权限，并在生成 apps.json 后再次核对。漏声明会停止发布，不自动放宽权限或关闭客户端校验。
- 201 提示明确说明“软件源未声明所需权限”，指导刷新软件源或联系维护者，保留具体权限详情，不再误导用户反复下载同一份文件。
- iOS、macOS 和 Windows 版本同步为 2.4.7，保留 2.4.6 的安装记录恢复、进度、常亮和主题修复。没有新的认证或 Windows 登录逻辑变更。

## 验证与边界

- 本地 7 项 Python 回归、4 项 iOS XCTest、元数据/repository/version contract 和 iOS/macOS 构建通过。
- 对同一份已发布 v2.4.6 IPA 验证：原更新源因漏声明 NSLocalNetworkUsageDescription 失败，修正后的权限清单及生成源均通过，覆盖主应用和扩展两个 bundle。没有修改旧 IPA 或绕过安全检查。
- 新标签 CI、下载后的新安装包校验和公开下载回读结果在发布完成后补记。旧客户端刷新源并完成实际更新仍待真机确认。
- IPA 未签名，需要服务端签名安装；macOS 使用 ad-hoc 完整性签名，未 Developer ID 签名或公证；Windows 二进制未签名。

## 更新步骤

在手机 AltForge 中先刷新官方软件源，再检查更新到 2.4.7。新的权限声明可由旧客户端读取，不需要先安装新版才能识别。若仍显示旧错误，先确认官方源已刷新，不要反复下载相同旧文件。

桌面端可同步更新到 2.4.7，但仅更新桌面端无法修复手机里缓存的旧源声明。手机应用内更新仍被旧认证逻辑阻断时，可使用新版电脑服务端覆盖安装手机端，保留现有数据，不要先卸载。

没有数据库或服务器协议迁移。旧版本安装包仍保留；回退到旧的 source metadata 会重新引入 201 错误，不建议以回退更新源排查此问题。后台安装后记录恢复及恢复后刷新仍由 ISSUE-20260905-003 跟踪真机验收。
