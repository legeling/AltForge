# AltForge v2.4.2

- 计划发布日期：2026-09-04（Asia/Shanghai）
- Tag：`v2.4.2`
- Commit、CI build、workflow 与产物 checksum：标签构建完成后回填

## 变化

- Apple ID 认证不再发送 2019 年 Xcode 11 的 `3594.4.19` 身份；Mac model、macOS version/build、CFNetwork 与 Darwin 来自当前运行环境，Xcode product/bundle identity 统一为当前 Xcode 27 beta 6 组合。
- 认证、2FA、Developer Services 和 AltForge Server anisette 数据共用同一身份，避免服务端把真实新系统与旧 Xcode 描述判为不一致。
- Apple 或网络中间层返回 HTML、空数据或畸形 plist 时，改为明确的 Apple 认证握手错误，不再让用户误以为 IPA 格式损坏。
- iOS、macOS 与 Windows 的产品错误统一为简短标题、对应原因和可执行建议；诊断信息继续保留错误域、代码和脱敏详情。

## 上游结论

- `altstoreio/AltStore#1772` 的登录 harness 确认 `3594.4.19` 会造成 2FA 循环，而动态的 Mac/系统 tuple 配合 `25183.54.10` 可以取得 Xcode token。
- `altstoreio/AltStore#1713` 的 Xcode 26.2 身份结论已用于交叉检查，但其 45 个文件包含广泛 CocoaPods 变更且当前合并冲突，因此不整包移植。
- `altstoreio/AltStore#1770` 的 macOS 26/27 anisette VM 属于独立兼容方案，包含 VM、内核、initramfs 和外部 Apple Music Android ADI 提取；本版不扩大权限、下载和运行时攻击面。

## 兼容性与升级

- iOS AltForge、macOS AltForge Server 与 Windows AltForge Server 产品版本统一为 `2.4.2`。
- 保持 Classic 形态、现有 bundle identifier、Core Data schema 与 Server Protocol，不需要数据迁移。
- 可直接通过 AltForge Server 覆盖安装 `2.4.1`；不要先删除 iOS App，以免同时删除本地数据。

## 已知限制

- 自动化能够验证代码、错误映射、三平台构建和产物结构，但不能替代真实 Apple ID、2FA、团队、证书与设备安装验证。
- macOS 26/27 在本机私有框架不再产生 anisette 数据时，本版仍依赖现有 AOSKit、XPC 或 Mail plug-in 路径；未纳入上游尚未合并的 VM 方案。
- IPA 由发布流程无签名构建；macOS DMG 使用 ad-hoc 签名且未 notarize；Windows ZIP 未代码签名。

## 预发布验证

- 版本、release metadata、repository、website、workflow YAML、Windows manifest 与 ldid architecture contracts 通过。
- iOS 26.5 Simulator 上标签流水线的 9 项定向 XCTest 全部通过。
- 本地完成 unsigned Release-iphoneos build、Universal macOS Release build、IPA/DMG 打包及 Apple artifact 校验；两端版本均为 `2.4.2 (999)`，macOS framework 包含 `27.0 (27A5252f)` / `25183.54.10` 且不含旧身份。
- Windows Release、GitHub 产物 build number、checksum 与下载回读由标签 CI 完成后回填。

## 回滚

若真实认证或安装出现阻断问题，可覆盖安装 `v2.4.1`。版本回退不迁移或删除数据库；AltSign 回滚必须同时恢复 nested commit 与主仓库 gitlink。
