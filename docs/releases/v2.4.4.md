## Changes

- Apple authentication errors identify the failed step and available HTTP status.
- Two-factor service failures no longer automatically appear as incorrect verification codes; malformed trusted-device replies cannot silently pass.
- Preserve structured Apple credential/anisette errors even on unsuccessful HTTP responses.
- Remove response fragments and arbitrary MIME/header values from parser diagnostics.
- macOS login errors wrap fully and can be selected; iOS copied reports include sanitized authentication diagnostics.

## Known limitations

Real Apple ID login, two-factor completion and device installation are not yet confirmed restored. This release corrects handling and diagnosis of failures, but cannot promise that Apple services will accept a given authentication request. Upstream HTML/503 reports are leads, not proof of the user's exact root cause.

The macOS updater from 2.4.3 remains available and downloads this version's verified DMG, then opens it. It does not silently replace the running app. macOS uses an ad-hoc integrity signature without Developer ID/notarization; the IPA and Windows ZIP are unsigned.

## Upgrade and rollback

Upgrade the desktop server and iOS app together for complete diagnostic wording. Preserve the existing iOS installation and its data. Roll back with the v2.4.3 packages if necessary; no database or credential migration is introduced.
