# AltForge v2.4.5

- Status: Release candidate; CI and downloaded-artifact verification pending
- Version: 2.4.5 for iOS AltForge, macOS AltForge Server and Windows AltForge Server
- Release: https://github.com/legeling/AltForge/releases/tag/v2.4.5
- Change: CHG-20260905-002
- AltSign commit: `9b06df71234804204bbbcb65ed135edd0d15b8cb` (published to legeling/AltSign)

## Changes

- Restore the GSA authentication compatibility identity using AuthKit instead of the old akd client family, adapting upstream AltSign PR #47.
- Adapt upstream AltSign PR #49's isolated ephemeral sessions and exponential backoff for transient GSA 5xx responses. Each exchange has at most five attempts and a 60-second budget; each attempt has a maximum 15-second timeout.
- Preserve explicit Apple errors. Wrong credentials, invalid anisette, HTTP 401/429, transport errors, timeouts and 2FA requests are not automatically retried. Diagnostics never include response bodies.
- Add four transport regressions to the release gate, covering recovery, exhaustion, session invalidation, error priority and deadlines.

## Verification

- All 17 selected XCTest passed locally, including the four new transport regressions. iOS test-host and macOS Universal Debug builds passed; the macOS test app passed deep/strict ad-hoc signature verification.
- The user confirmed successful macOS sign-in with the local candidate and showed the device preparation/registration stage. The login blocker reported in 2.4.4 is cleared in that test.
- Tag-driven CI, public package checksums and final Release publication remain pending at preparation time.

## Known limitations

Final device installation, all 2FA variants, independent iOS sign-in and Windows sign-in were not confirmed by this test. Windows receives the synchronized version bump and a fresh CI build, but its separate C++ authentication implementation is unchanged. Do not present the Apple-platform authentication patch as a Windows login fix.

The IPA is unsigned and requires AltForge Server to sign/install it. macOS uses an ad-hoc integrity signature without Developer ID or notarization; Windows binaries are unsigned.

## Upgrade and rollback

Update the desktop server first, then update the iOS app while preserving its data. The existing macOS updater downloads a verified DMG and opens it; drag the app to Applications after quitting the older server. It does not silently replace a running app. No database or credential migration is introduced.

Rollback packages remain available in v2.4.4, but that version may reproduce the old GSA sign-in failure. Never delete the existing iOS app just to update it.
