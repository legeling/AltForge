# 上游 Issue 审计方法

## 数据来源

- 仓库：[`altstoreio/AltStore`](https://github.com/altstoreio/AltStore)
- 最后核对：2026-08-11
- 查询范围：全部开放 Issue，不包含 Pull Request
- 获取字段：编号、标题、正文、状态、创建/更新时间和 labels

审计输入一次获取 645 条记录。获取后先验证结果非空、未触及 1000 条查询安全上限、编号唯一且所有状态均为 Open。正文只用于本次分类和人工判断，不写入仓库。

## 分类流程

1. 用标题、正文和 labels 执行多标签匹配，为每条记录产生候选主题。
2. 按候选主题输出完整标题清单，而不是只抽样热门或最近 Issue。
3. 人工逐组复核 645 条标题，对明显误分类做显式覆盖。
4. 根据共同代码所有者、失败阶段、风险和验证门禁决定是否合并到本地 Issue。
5. 生成 15 份主题报告、完整 Markdown 附录与机器可读 JSON，并验证三者编号集合一致。

自动规则的时间复杂度随 Issue 数量线性增长，约为 `O(n × r)`，其中 `r` 是固定数量的分类规则；当前数据规模下不会产生无界请求或并发。生成阶段只读取一次 JSON，并按主题分组后顺序写文件。

## 分类不是根因结论

同一主题中的报告可能来自不同系统版本、设备、网络、账号或第三方 IPA。分类只回答“由哪组维护门禁接住”，不证明根因相同，也不证明 AltForge 已复现或已修复。

本地 Issue 只有在具备影响、证据、临时规避、完成条件和 `FR/DES/TEST/T/CHG` 关联时才成立。单个上游标题不会自动成为本地任务。

## 隐私与安全

仓库保留：

- Issue 编号、标题和 URL
- 状态、创建/更新时间和 labels
- 分类、处置和本地 Issue 映射

仓库不保留：

- Issue 正文、评论、附件和作者信息
- Apple ID、密码、2FA、Cookie、anisette 数据
- UDID、设备名、证书、私钥和 Provisioning Profile

需要真机复现时只记录脱敏环境矩阵、失败阶段、错误域/代码和验证结果。

## 可重复生成

主题报告由以下脚本根据 JSON 审计源生成：

```sh
ruby Scripts/generate_upstream_issue_topic_docs.rb
```

脚本会拒绝未配置的新分类、审计中缺失的分类以及无法解析的本地 Issue 映射，避免静默丢条目。
